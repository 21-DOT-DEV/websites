## Why this matters

When you expand a module in the DocC sidebar at `https://docs.21.dev/documentation/`, the first thing a reader sees should be the *authored articles* — the high-information curated guides (Getting Started, How-To, conceptual explanations). Today the `Event` module does this well:

```
Event
  Guides
    Getting Started with Event in Swift
    How to Write an Async TCP Server in Swift
    Async TCP Client for iOS in Swift
    Handling Partial Reads in Swift TCP Sockets
    Choosing Between Event and libevent
    Embedding a C Library in Swift Package Manager
    swift-event vs SwiftNIO vs Hummingbird vs Network.framework
  Concepts
    Backend and Platforms
    Production Considerations
  Essentials
    EventLoop
    Socket
    ServerSocket
  …
```

For Bitcoin and BitcoinKernel, articles are either *missing from a top group entirely* (Bitcoin) or *split across two separate groups* (BitcoinKernel) — readers have to scroll past dozens of type entries to discover the guides.

DocC controls this via the `## Topics` section in the module's main `.docc/<Module>.md` file. Each `### Subgroup` becomes a sidebar section in the rendered navigation. The order of `### Subgroups` is the order they appear in the sidebar.

## How to verify the fix locally before tagging upstream

After editing the two `.docc/<Module>.md` files in the swift-bitcoinkernel repo, build the doccarchives:

```bash
xcodebuild docbuild -scheme Bitcoin \
  -destination 'generic/platform=macOS' \
  -derivedDataPath ./derived
xcodebuild docbuild -scheme BitcoinKernel \
  -destination 'generic/platform=macOS' \
  -derivedDataPath ./derived
```

Then inspect the resulting `*.doccarchive/data/documentation/<module>.json` `topicSections` field — `### Guides` should be the first entry with both authored articles for BitcoinKernel, and Bitcoin's `gettingstarted` should appear under a new top `### Guides` group.
