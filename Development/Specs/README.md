# Specs

One directory per feature: `NNN-slug/` containing `plan.md` plus whatever
companion documents the feature earned — a schema it defines, an interface it
exposes, a runbook it leaves behind. Companions are added because the feature
needs them, never "just in case". Start new features from `_template/`.

## Conventions

- `plan.md` opens with YAML frontmatter the checker validates:
  `feature` (the directory's `NNN`), `title`, `phase` (a roadmap phase name or
  `null`), `status` (`Planned`, `In Progress`, `Implemented`), `updated`
  (`YYYY-MM-DD`, bumped on every revision), `adrs` (ADR numbers this plan
  relies on).
- The plan is a living document — rewrite it as understanding changes; never
  append log-style sections. A `## Tasks` section lists unchecked work that
  remains, each with an owner, an exit condition, and its verifying test or
  command.
- Test counts are deltas (`+7 tests`), never suite totals.
- Feature numbers are issued in order and never reused.
